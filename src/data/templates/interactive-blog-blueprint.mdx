Technical writing is most effective when readers can interact with concepts rather than just read about them. This article serves as **both an interactive demonstration and your reference blueprint** whenever you write new posts for this site.

Every component used here (`Callout`, `Tabs`, `InteractiveDemo`, code highlighting, tables, and typography) is built into the site's MDX engine and works out of the box.

---

## 1. Frontmatter Specification

Every article begins with a YAML frontmatter block at the very top of the `.mdx` file inside `src/data/blogs/<slug>.mdx`:

```yaml
---
title: "Your Article Title"
date: "2026-10-04"
description: "A punchy 1-2 sentence summary that appears on the card preview and Google SEO."
image: "/gradient.png" # Optional: file path in public/ or external URL
tags: ["C++", "QML", "Systems"]
---
```

<Callout type="tip" title="SEO & Reading Time">
Reading time is calculated dynamically at build time based on your word count. The `description` and `image` are automatically mapped into Next.js OpenGraph and Twitter card meta tags.
</Callout>

## 2. Rich Contextual Callouts

Callouts help highlight critical notes, performance pitfalls, pro-tips, or quotes without disrupting the narrative flow.

<Callout type="info" title="Architecture Note">
Use `info` callouts for background context, architectural rationale, or platform-specific prerequisites (such as Qt 6.8+ or Linux kernel requirements).
</Callout>

<Callout type="tip" title="Performance Optimization">
Zero-copy serialization with `std::span` avoids redundant allocations across the C++ and UI boundaries. Prefer passing memory buffers by `const ref` whenever possible.
</Callout>

<Callout type="warning" title="Threading Boundary Warning">
Never update UI elements directly from a background worker thread. Always dispatch updates back to the main event loop via signal/slot mechanisms or thread-safe message queues.
</Callout>

<Callout type="idea" title="Conceptual Insight">
Think of your user interface as a pure projection of system state over time: `UI = f(State)`.
</Callout>

<Callout type="quote" title="Guiding Principle">
"Premature optimization is the root of all evil, yet lack of architectural thought guarantees sluggish software."
</Callout>

## 6. Quick Reference Checklist for Future Articles

When writing your next post:

1. **Create the file**: Add `src/data/blogs/your-topic-slug.mdx`.
2. **Add frontmatter**:
   - `title`: Keep it descriptive and punchy.
   - `date`: YYYY-MM-DD format.
   - `description`: Crisp summary for search engines and cards.
   - `image`: Add an image in `public/` (e.g. `/my-article.png`) or use an existing asset.
3. **Use MDX elements**:
   - `<Callout type="info|tip|warning|idea|quote" title="...">`
   - `<Tabs items={["Tab 1", "Tab 2"]}> <Tab>...</Tab> </Tabs>`
   - `<InteractiveDemo title="..." description="..." code="...">`
4. **Build check**: Run `pnpm build` to verify MDX parsing and static generation.
